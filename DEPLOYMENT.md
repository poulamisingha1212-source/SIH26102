# MPLADS AI Sentinel — Deployment Guide ($0/month)

## Architecture

```
                ┌────────────────────┐
  Browser  ───► │  Vercel (Frontend) │  React/Vite SPA — free static hosting
                └────────────────────┘
                         │ HTTPS API calls (VITE_API_URL)
                ┌────────────────────┐
                │  Render.com (API)  │  FastAPI — free Web Service
                └────────────────────┘
                         │ pymongo (SRV)
                ┌────────────────────┐
                │  MongoDB Atlas M0  │  512 MB free cluster (permanent)
                └────────────────────┘
```

> **Free-tier constraints:**
> - Render free Web Services spin down after 15 min of inactivity (cold-start ~30 s).
> - MongoDB Atlas M0 = 512 MB storage, shared cluster, no VPC peering.
> - Vercel Hobby = unlimited static deploys, 100 GB/month bandwidth.

---

## Step 1 — MongoDB Atlas (database)

1. Sign up at **https://cloud.mongodb.com** (free, no credit card).
2. Create a new **M0 free cluster** (any region — pick one close to your Render region, e.g. Oregon).
3. **Database Access**: create a database user:
   - Username: `mplads`
   - Password: generate a strong random password and save it.
   - Role: **readWriteAnyDatabase**
4. **Network Access**: add `0.0.0.0/0` (allow all IPs) — required for Render's dynamic IPs.
5. Click **Connect → Drivers** and copy the **SRV connection string**:
   ```
   mongodb+srv://mplads:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```
   Replace `<password>` with the password you created.

---

## Step 2 — Render.com (FastAPI backend)

1. Sign up at **https://render.com** (free, GitHub login).
2. Click **New → Web Service**.
3. Connect your GitHub repository.
4. Render will auto-detect `render.yaml` and pre-fill all settings.
5. In the **Environment Variables** section (Render dashboard), manually add the sensitive values that are marked `sync: false` in `render.yaml`:

   | Variable | Value |
   |---|---|
   | `MONGODB_URI` | The SRV string from Step 1 |
   | `CORS_ORIGINS` | Your Vercel URL (Step 3), e.g. `https://mplads-sentinel.vercel.app` |
   | `DEMO_ADMIN_USER` | Pick a strong admin username |
   | `DEMO_ADMIN_PASSWORD` | Pick a strong password (min 12 chars) |

   > `JWT_SECRET` and `CRON_SECRET` are auto-generated by Render (marked `generateValue: true`).

6. Click **Deploy**. Wait for the build to complete (~3–4 min).
7. Verify: open `https://<your-render-service>.onrender.com/api/health` — you should see `{"status":"ok", ...}`.
8. **Copy the Render service URL** — you'll need it for Vercel.

---

## Step 3 — Vercel (React frontend)

1. Sign up at **https://vercel.com** (free, GitHub login).
2. Click **Add New → Project** and import your GitHub repository.
3. Vercel will auto-detect the `vercel.json` in the root. Settings:
   - **Framework Preset**: Other (vercel.json handles it)
   - **Root Directory**: `. ` (repository root)
4. Add environment variable:

   | Variable | Value |
   |---|---|
   | `VITE_API_URL` | Your Render URL, e.g. `https://mplads-sentinel-api.onrender.com` |

5. Click **Deploy**. The build runs `cd frontend && npm ci && npm run build`.
6. Verify: open the Vercel URL — the app should load and call `VITE_API_URL/api/stats/overview`.

---

## Step 4 — Wire CORS

Once you have your Vercel URL, go back to your Render service:
1. Open **Environment → `CORS_ORIGINS`**.
2. Set it to your Vercel URL (no trailing slash):
   ```
   https://mplads-sentinel.vercel.app
   ```
3. Render will **auto-redeploy**. The backend now accepts requests from the frontend domain.

---

## Step 5 — GitHub Actions secrets

For automated CI/CD (tests run on every push, frontend auto-deploys on main):

1. In your GitHub repo → **Settings → Secrets and variables → Actions**, add:

   | Secret | Where to get it |
   |---|---|
   | `VITE_API_URL` | Your Render service URL |
   | `VERCEL_TOKEN` | Vercel dashboard → Account Settings → Tokens |
   | `VERCEL_ORG_ID` | Vercel project settings → General |
   | `VERCEL_PROJECT_ID` | Vercel project settings → General |

2. Tests run automatically on every push (`.github/workflows/test.yml`).
3. Frontend deploys to production on every push to `main` (`.github/workflows/deploy-frontend.yml`).

---

## Step 6 — Verify end-to-end

Open your Vercel URL and check:

- [ ] **Overview tab** loads with portfolio statistics
- [ ] **Priority Queue** shows works with risk scores  
- [ ] **Login** with your `DEMO_ADMIN_USER` / `DEMO_ADMIN_PASSWORD` credentials
- [ ] **Human review** submission works (requires reviewer role)
- [ ] `/api/health` returns `"status": "ok"` and `"database": "connected"`

## Nightly Sync (Vercel Cron — alternative)

> This is only needed if you want scheduled live data pulls. Skip if you trigger
> syncs manually or use the Render-hosted APScheduler (default).

The nightly live sync is already configured in the backend APScheduler (runs at 19:00 IST).
If you prefer Vercel Cron instead, restore the `crons` block to `vercel.json`:

```json
"crons": [
  { "path": "/api/cron/sync", "schedule": "30 13 * * *" }
]
```

This calls `GET /api/cron/sync` on your **backend** (not Vercel) using the `CRON_SECRET` as Bearer token.

## Local Development

```bash
# Backend
python -m uvicorn backend.main:app --reload --port 8000

# Frontend (in a separate terminal)
cd frontend
npm install
npm run dev
```

The frontend dev server proxies `/api`, `/works`, `/stats`, and `/sync` to `localhost:8000`.
Copy `.env.example` to `.env` and fill in your values.

## Docker (self-hosted / HuggingFace Spaces)

```bash
docker build -t mplads-sentinel .
docker run -p 7860:7860 \
  -e MONGODB_URI="mongodb+srv://..." \
  -e JWT_SECRET="your-secret" \
  -e CORS_ORIGINS="http://localhost:7860" \
  mplads-sentinel
```

The Docker image serves both the API and the bundled React SPA on port 7860.
See `README_HUGGINGFACE.md` for HuggingFace Spaces-specific instructions.

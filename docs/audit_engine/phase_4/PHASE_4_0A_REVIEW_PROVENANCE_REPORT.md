1. `MPLADS23-TIME-001` (45-Day Decision Window): Requires `recommendation_date` and `sanction_date`. Both fields are 0.0% populated in MongoDB. Produces **228,328 UNKNOWNs**.

4. `MPLADS23-FIN-003` (Annual Allocation Entitlement Ceiling): Requires multi-year cumulative carry-forward ledgers. 0.0% present in the single-work record. Produces **228,328 UNKNOWNs**.

Because each work record is evaluated against all 17 rules, having even one globally unavailable field causes that work to receive `UNKNOWN` on that rule.  
**Critical Principle:** `UNKNOWN` denotes an **evidence absence in the portal schema**, NOT an audit defect, suspicion, or failure.

## 11. Root-Cause Classification

The root cause of the large (110,940) REVIEW count is:
```text
STATUTORY_STATUS_MAPPING_CHOICE
```
It is NOT a software defect, NOT legacy leakage, and NOT a database corruption.  
It is the direct, intended outcome of `model/rules/evaluator.py:L517`:
```python
state = RuleState.REVIEW if str(row.get("work_status")).strip() == "Physical Inspection" else RuleState.UNKNOWN
```

In MoSPI portal practice, when a work reaches completion, the District Authority marks its status as `Physical Inspection` while awaiting physical site verification by the District Planning Officer (under the 10% statutory inspection quota mandate). Because 110,868 works in the database are currently in this active administrative stage, `model/rules/evaluator.py` flagged all of them as `REVIEW` to signify that their physical inspection log requires verification.
